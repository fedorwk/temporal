# Design Decisions

Decisions not settled by `temporal_series_requirements.md`, or deviations from it. The spec stays authoritative for everything not listed here.

## Pre-coding decisions (from IMPLEMENTATION_PLAN.md §3)

| ID | Topic | Decision | Spec refs |
|---|---|---|---|
| P-01 | Module path | `github.com/fedorwk/temporal` (settled 2026-10-11; renaming later is a one-line `go.mod` change plus import rewrites). Package lives at the module root (moved from `temporal/` by S12-03). | §26 |
| P-02 | Batch conflict semantics | **Settled. Sequential**: item *i* conflicts with rows still retained when item *i* is applied (i.e. not evicted by items 0..*i*, including itself) and with earlier applied items. `AppendBatch(items)` ≡ the same `Append` calls in order, except all-or-nothing and one notification. Reason: a whole-transaction "rows this transaction evicts" rule is circular when Drop outcomes change how many rows get evicted. Also gives a simple test oracle. | §9.3, 9.4, 10.3, E-012 |
| P-03 | Prepare-phase order and precedence | Per item: (1) validate sentinels/flag bits → (2) late check + LatePolicy → (3) SourceSeq check + policy → (4) Seq-exhaustion check → (5) Clone (OnWrite) → (6) per index in `Config.Indexes` order: extract + conflict. Any Reject anywhere fails the call; else any Drop drops the item. Dropped items do not update MaxObservedEventTime, the SourceSeq tracker, or record counters other than `Dropped`. | §9.2, 9.3, 10.3 |
| P-04 | "No state change" vs diagnostic counters | **Settled.** `Stats.Rejected` and `IndexStats.Conflicts` increment on failed appends (operators of a live feed need to see rejections; otherwise they are invisible). "No state change" means data state: ring, bounds, Seq, Gen, indexes, trackers, envelope, watermark. | §9.5, 21 |
| P-05 | `ReadInfo.Evicted` intervals | Range: `[from,to)` vs `[MinEvicted,MaxEvicted]`. AtAll: `[ts,ts+1)`. Continue: `[last.EventTime, bound)`. PrevN: `HasEvicted && MinEvicted <= ts`. NextN: `HasEvicted && MaxEvicted > ts`. ReadFrom: true iff status is Expired. | §7.2, 7.4, 8.4 |
| P-06 | ReadFrom edge cases | `from.Seq == 0` → start at Oldest, Gen ignored. `from.Gen < Gen` (Seq≠0) → Reset. `from.Gen > Gen` → NotFound. `ReadInfo.Next` always zero; continuation via `LastRef.Seq+1`. | §7.2, 8.1, Q-007 |
| P-07 | Subscription edge cases | StartOldest on empty series → `Next = Newest+1`. `StartAt(zero Ref)` ≡ StartOldest. `StartAt` with `ref.Gen > Gen` → first `Next` returns `ErrInvalidInput`. `Subscribe` on a closed Series succeeds and drains retained records, then `ErrClosed` (consistent with E-013). `limit <= 0` → MaxReadBatch. | §17 |
| P-08 | Close idempotency | `Series.Close` returns nil on every call; only writes/Clear/SetWatermark observe the closed state. `SetWatermark` after Close returns false. | §15.4, E-013 |
| P-09 | Empty AppendBatch | No-op: returns `dst` unchanged, nil error, no Seq, no wake. Closed check still first (`ErrClosed`). | §9.4 |
| P-10 | Overflow-safe arithmetic | Late threshold uses saturating `MaxObserved - LateTolerance`. Gating: `Range` gated iff `to != MinTimestamp && to-1 > wm`; same for cursor bounds. `LateTolerance < 0` → `ErrInvalidConfig`. | §5.3, 19 |
| P-11 | Index prepare signature | Replace `willEvict func(Seq) bool` with `evictBelow Seq` (evictions are always a prefix from Oldest) → no closure allocation. Batches use per-index typed scratch (`[]K` by batch position + reusable pending `map[K]pendingRef`, cleared with `clear`). | §10.2 |
| P-12 | Deriver needs consistent source snapshot | Internal subscription method returns the batch together with `{newest, watermark, maxObserved, gen}` captured under the same lock. Deriver keeps its own `processed` cursor, advanced only after `dst.AppendBatch` succeeds. A panic in the derive function is recovered and treated as a derive error. | §18.1, 18.4 |
| P-13 | Watermark gate for forward reads | **Settled, overrides §19's "always" rule.** Gating stays off by default. With `GateReadsByWatermark`, before the first `SetWatermark` the watermark is MinTimestamp. Backward reads gate as written in §19. Forward reads are gated on the *answer*, not the query: a record with EventTime <= watermark is final (no late arrival can land between `ts` and it), so it may be returned. `After`/`AtOrAfter`: find the match as usual; if it exists and its EventTime <= wm → OK; otherwise NotReady (if no match and the envelope says Expired, Expired wins as in the normal precedence, since evicted data never returns). `NextN`: return matches with EventTime <= wm, up to n (bound = `wm+1`, saturating); if none → NotReady; `Truncated` when the cap n or MaxReadBatch cut off more matches <= wm. Reason: the library targets live trading (trades, order-book updates); "always NotReady" would make forward reads useless on gated series, while this rule keeps the no-look-ahead guarantee that gating exists for. Record the deviation in `DECISIONS.md`. | §19 |
| P-14 | TimeCursor encoding | `series` = global atomic counter starting at 1 (0 = never valid). `state = {uint64(last.EventTime), last.Seq, uint64(bound)}`. Cursor gen > current gen → Invalid. | §8.4 |
| P-15 | Entries iterator | One page buffer allocated per `Entries` call. If a later page returns non-OK (e.g. Reset after Clear), iteration ends silently; documented. | §8.3 |
| P-16 | Ring layout | Struct-of-arrays: `values []T` and `meta []slotMeta{eventTime, receiveTime int64; sourceSeq uint64; epoch, flags uint32}` (32 B/slot). Seq not stored, except a debug-only `seq []Seq` under `temporaldebug`. Bounds live in a small `bounds` value type inside the Series. | §12 |
| P-17 | Clone configured with nil func | `CloneMode` is ignored when `Clone == nil`. | §11.5 |
| P-18 | Error-path reflection | `ConflictError.Key` uses `fmt.Sprint(k)` on the error path only; acceptable under "no reflection on normal paths". | §9.5, 31 |
| P-19 | Implementation order | Key indexes (S6) **before** AppendBatch (S7), so the batch simulation is written once against the final index interface. Swaps spec §30 steps 6 and 7. | §30 |

| S12-01 | post-plan | **Panics are the caller's responsibility (deviates from W-004/E-007/T-014 and §27).** The library no longer recovers panics: `CallbackPanicError` and `ErrCallbackPanic` are removed, and a panic in Clone or a key extractor propagates out of Append/AppendBatch. The library stays panic-safe: callbacks run only in the prepare phase, before any mutation; Append/AppendBatch release the lock with `defer`, and the CloneOnWrite scratch, the extractor scratch entry and the unique-index pending overlay are cleaned up by `defer`. A caller that recovers finds the Series unchanged (counters included: `Stats.Rejected` does not move on a panic) and usable. Cost: the deferred unlock is used only when user code can run (CloneOnWrite or key indexes; fixed at New); the no-callback path keeps an explicit unlock and is exactly as fast as before (Append 25.7 ns None / 95.6 ns BTree). The callback path costs ~+4 ns per Append (unique index: 97.8 → 102 ns), the irreducible price of a defer; AppendBatch is unchanged within noise. | Idiomatic Go (sort, sync, errgroup pass callback panics through); a panicking callback is a bug and should not look like an ordinary rejection; simpler API and slightly cheaper indexed appends. Decided by the user on 2026-10-11. | §9.3, §27, W-004, E-007, T-014 |

In their place, `Subscription.NextState` returns the records plus a public `SourceState{Gen, Newest, Watermark, MaxObservedEventTime}` captured under the same lock (the P-12 snapshot, now public, zero on error), and `ExampleSubscription_NextState` documents a complete derive loop (atomic append per batch, checkpoint after success, watermark forwarded when caught up). The S9 "unset" StartFrom kind is reverted: the zero value is StartNext. Supersedes S9-01..S9-06. | Leaves concurrency, retries, multi-input joins and panic policy to the caller (Go practice; the spec already puts multi-series coordination in a higher layer). | S12-04 | post-plan | **Third time-index mode, `TimeIndexOrdered` (deviates from A-02's two v1 modes).** For feeds whose EventTime never decreases, the retained records in Seq order are already sorted by `(EventTime, Seq)`, so `orderedTimeIndex` stores no keys: it tracks the indexed Seq interval (`first`, `n`) and answers every `timeIndex` primitive by binary search over the ring's metadata (`metaRing`, the non-generic half of `ring[T]`, split out so the index does not depend on T). The ordering is enforced by configuration, not new write-path code: `New` requires `LatePolicy: LateReject` and `LateTolerance: 0` (ErrInvalidConfig otherwise), so the existing late check rejects any record below the generation's MaxObservedEventTime with ErrLate; ties are allowed; Clear starts a new timeline. Explicit configuration was chosen over silently overriding the late policy so the rejection behavior is visible in the caller's config. `Apply` is O(1) in normal builds (move the bounds); debug builds check every key (contiguous Seqs, FIFO deletes, nondecreasing EventTime, key matches the ring). Measured: Append 27.0 ns (None 25.7, BTree 95.4), AppendBatch +5-10% over None with 0 allocs, AsOf 115 ns (BTree 154), Range 256 1.5 µs (BTree 2.2 µs), 0 extra bytes per row. | Live trading feeds from one source usually arrive in event-time order; they get every event-time query at almost the cost of TimeIndexNone. Out-of-order feeds keep TimeIndexBTree. Requested by the user on 2026-10-11. | §13, A-02, A-03, TI-008, W-009, W-010 |
| S12-05 | post-plan | **Close with a cause.** `Series.CloseWithError(cause)` closes like `Close` (which is now `CloseWithError(nil)`) and records the cause, readable with `Err()`. Every place that reported the closed Series with `ErrClosed` (Append, AppendBatch, Clear, a drained subscription's Next/TryNext) now returns a precomputed `closeErr`: `ErrClosed` for a clean close, otherwise one `*ClosedError{Cause}` whose `Is(ErrClosed)` is true and whose `Unwrap` is the cause. It is allocated once at close, so the error paths stay allocation-free. The first close wins; later calls change nothing. A subscription's own `Close`/`Seek` keep plain `ErrClosed`, since that is about the subscription, not the Series. | A feed adapter that fails must tell every downstream reader why the series ended; from outside this needs a side channel per series. ## Lock-discipline audit (Session 10)

Every acquisition of a Series mutex (`s.mu`), as of commit "session 10", updated for S12-01/S12-02. "deferred" means `Lock()` is immediately followed by `defer Unlock()` (C-007).

| Site | Kind | Unlock | User code under the lock | Panic safety |
|---|---|---|---|---|
| `Append` (series.go, `appendTx`) | write | deferred; `sig.records()` runs after `appendTx` returns | Clone (CloneOnWrite); extractors via `keyCore.extract` — prepare phase only | panics propagate after the deferred unlock; nothing was mutated yet; `keyIndexes.prepare` zeroes the scratch entry by `defer`; the commit phase calls no user code (§9.3) |
| `AppendBatch` (batch.go, `appendBatchTx`) | write | deferred; `sig.records()` runs after `appendBatchTx` returns | same as Append, per item, prepare phase only | same; the clone scratch is cleared and index batches are ended by `defer`, also during a panic |
| `Clear`, `Close` (series.go) | write | explicit, before `sig.records()` / `sig.closed()` | none | no user code |
| `SetWatermark` (watermark.go) | write | explicit, before `sig.watermark()` | none | no user code |
| `Watermark`, `WaitWatermark` (watermark.go) | read | deferred / explicit before blocking | none | — |
| `Len`, `Gen`, `OldestRef`, `NewestRef`, `Stats`, `CheckInvariants` | read | deferred | none | — |
| `Get`, `Latest`, `ReadFrom` (query.go) | read | deferred | Clone (CloneOnRead) in `copyOut` | panic propagates after the deferred unlock (T-015) |
| point reads (query_time.go, 7 sites) | read | deferred | Clone (CloneOnRead) in `copyOut` | same |
| batch reads `Range`, `RangeValues`, `AtAll`, `Continue`, `ContinueValues`, `PrevN`, `NextN` (query_batch.go) | read | deferred | Clone (CloneOnRead) in `copyEntries`/`copyValues` | same |
| `Entries` status check (query_batch.go) | read | explicit, no code between | none | pages use `Range`/`Continue` (deferred); nothing is yielded under the lock (C-008) |
| key lookups via `keyCore.lockedSeries` (key_index.go, 8 methods) | read | deferred by each caller | Clone (CloneOnRead) in `copyOut` | same as other reads |
| `Subscribe`, `unsubscribe`, `poll`, `Seek` (subscription.go) | read/write | deferred | Clone (CloneOnRead) in `poll` | cursor and `skipped` change only after the copy succeeds (S-005) |

Other synchronization:
- `bindMu` (package-level) serializes index binding in `New`; it is held only inside `New`, while the new Series is not yet visible to any other goroutine, so no lock-order cycle with a Series mutex is possible.
- `changeSignal` (S13-02) wakes subscriptions and WaitWatermark callers, always after the Series mutex is released (C-005). Its subscriber list is an `atomic.Pointer` replaced copy-on-write under `s.mu` and read without a lock. Its own mutex guards only the WaitWatermark channel; it is taken inside `s.mu` by WaitWatermark and outside it by the reports, never the other way round, so there is no lock-order cycle.
- The library starts no goroutines (S12-02); derive loops run on the caller's goroutines, outside every Series lock.
- Index implementations (time and key) hold no locks and call no user code or Series methods (T-025 enforces the lock part structurally).
